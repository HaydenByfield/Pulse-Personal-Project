# Pulse-Personal-Project
Develop the frontend for your own personal responsive website ensuring you follow the principles of refactoring a UI.

# Getting Started

Create a new Next.js app named my-app without preferences or defualt prompts

```bash
npx create-next-app@latest my-app --yes
```
-----------------------------------------------------
Create a new Next.js app named my-app with all prompts

```bash
npx create-next-app@latest
```
-----------------------------------------------------
Create a new Next.js app manually adding scripts to selected packages

```bash
npm i next@latest react@latest react-dom@latest
```
-----------------------------------------------------

Route to app package to start local Next.js app Server

```bash
cd my-app
npm run dev
```
-----------------------------------------------------
To keep Next.js up to date you need to run the upgrade command

``` bash
npx next upgrade
```
-----------------------------------------------------

# Notes

Top Level Folders are used to organize code and    staic assests. These folders include:

1. app - App router used to represent the pages layouts, loading states , error handling and route handlers
2. pages - Pages router is an older roting system, that is still supported
3. public - Stores static assests such as images, icons and other assests.
4. src - That is a separate directory. That you can place app/ or pages/ alongside other components and utilities
-----------------------------------------------------

Top level Files ares used to configure your application, manage dependencies, run proxy,
integrate monitoring tools, and define environment variables.

1. next.config.js - configuration file for Next.js
2. package.json - Project dependencies and scripts
3. instrumentation.ts - OpenTelemetry and Instrumentation file(Monitoring and tracking requests and errors)
4. proxy.ts - Next.js request proxy(Allows you to intercept a request and run logic before the request is processed/completed)
5. .env - Environment variables(Should not be tracked by version control)
   * .env.local - Is a file that has the highest priority of all .env files and is mainly usedwhen you want values specific to your own computer
   * .env.development - Is a file that holds all personal sensitive and secure data, values such as APIs, server and database URLs, however all these done within the development stage. Therefore, mainly environmental varibales for testing(npm run dev)
   * .env.production -  Is a file that holds all personal sensitive and secure data, values such as APIs, server and database URLs, however all these are used in the production stage or when building the live application. Therefore, mainly environmental varibales for production(npm run build, npm run start) 
6. eslint.config.mjs - Configuration File for ESLint(Examines code and warn about inconsistent code and practices, alongside unused variables. It promotes code quality)
7. gitignore - git files and folders to ignore
8. next-en.d.ts - TypeSctipt declaration file that should not be tracked
9. tsconfig.json - Configuration file for TypeScript
10. jsconfig.json - Configuration file for JavaScript
